# Hands-on AWS CLI teaching track (not Terraform-owned)

## Ground rules
No command was executed against AWS while creating these materials. These are runnable guarded teaching scripts, not claimed cloud-tested automation. Read COSTS.md/PERMISSIONS.md; use a disposable sandbox. AWS CLI v2 provisions AWS resources; **kubectl applies Kubernetes objects**; Helm installs the controller chart; AWS CLI alone cannot apply a Deployment YAML. No eksctl/Terraform dependency in primary CLI path.

Never source or execute config downloaded from strangers. Copy `config.example.env` to `config.env`, fill real sandbox account/role/public /32/region. Configure temporary credentials through approved SSO outside these scripts. Choose a UNIQUE `eksclass-cli-*` stack. State in `.state/<stack>/resources.json` contains IDs and kubeconfig, not intentionally credentials; keep it private and never commit it. Scripts must run serially, one operator, no parallel state writes. Primary creation stages persist each new ID and reuse it on ordinary rerun; they don't reconcile arbitrary drift, verify every prior route is still correct, or guarantee recovery after a network timeout between successful API create and state write. Inspect errors and exact stack tags before retry. Do not erase state to retry. Guarded scripts intentionally fail if prerequisites are unknown.

Images: use a reviewed **digest** for APP_IMAGE implementing agnhost 2.53 netexec behavior, a compatible AWS CLI v2 image and DEBUG_IMAGE implementing BusyBox sh/nslookup/wget. Example source tag can be inspected with `docker buildx imagetools inspect registry.k8s.io/e2e-test-images/agnhost:2.53` on your workstation; review platform-specific versus manifest-list digest and scan it, then set `registry...@sha256:<actual-reviewed-digest>`. Do not paste a made-up digest. Fetch/verify image metadata in the normal approved tooling; source artifacts deliberately do not invent current digest values. Pin and verify chart appVersion v3.6.2. Exact addons are discovered once and recorded, not hand-guessed. These intentional placeholders are release gates, not secret values to supply to this author.

Run from labs: `bash scripts/00-preflight.sh`, inspect; only then set `COST_ACK=I_ACCEPT_BILLABLE_SANDBOX` in config.env for creation. Do not run “all scripts” blindly; lab numbering below is teaching order, script numbers are implementation files. Export the printed dedicated KUBECONFIG in every separate terminal. If access was changed to private-only, run kubectl/controller teardown from the tested private runner.

## Namespace viewer (four-identity exercise)
Use a DIFFERENT pre-existing sandbox IAM role `VIEWER_ROLE_ARN`, never the bootstrap admin role. With admin context:
```bash
aws eks create-access-entry --cluster-name "$STACK" --principal-arn "$VIEWER_ROLE_ARN" --type STANDARD --kubernetes-groups eksclass-viewers
kubectl -n eksclass create role class-view --verb=get,list,watch --resource=pods,services,deployments.apps
kubectl -n eksclass create rolebinding class-view --role=class-view --group=eksclass-viewers
# Use a separate kubeconfig with viewer's IAM role. kubectl get pods -n eksclass allowed;
# kubectl get secrets -n eksclass and delete deployment/web denied. It needs eks:DescribeCluster
# and caller sts:AssumeRole to build/use kubeconfig, but NO EKS admin access policy.
```
Exact cleanup: delete class-view rolebinding/role if namespace still exists; `aws eks delete-access-entry --cluster-name "$STACK" --principal-arn "$VIEWER_ROLE_ARN"`. This optional access entry must be removed/recorded before final cluster deletion; does not delete the pre-existing IAM role.

2. **DNS/TLS**: owned hosted zone, ACM request-certificate in region for owned name, describe-certificate to obtain DNS validation, deliberate Route53 change batch, ACM certificate-validated waiter; exact Ingress certificate ARN/listen-ports/ssl-redirect; Route53 alias target LB canonical hosted zone. 3. **Gateway**: Standard LBC v3.6.2 + pinned Gateway API v1.6.0 standard CRDs + extension CRDs from SAME controller release (not mutable main); inspect chart/controller feature defaults and conformance. 4. **EFS**: create owned encrypted test filesystem, mount targets in BOTH private AZs, target SG allow TCP2049 from actual node/Pod SG; dedicated EFS CSI role service-role/AmazonEFSCSIDriverPolicy, compatible addon; StorageClass efs.csi.aws.com efs-ap with exact filesystemId, mode700/UID/GID plan; PVC RWX + two consumers; test shared write; remove consumers/PVC/access points/mount targets/filesystem with backup decision. 5. **CA**: approved compatible CA build (version matches cluster minor) on stable capacity, discovery tags on explicit MNG ASG, dedicated IAM role, min/max constraints; requests-driven unschedulable Pod test; inspect events and ASG desired vs HPA replicas. This CLI bundle must not modify its VPC, cluster, IAM or addons.

## Troubleshooting decision tree
- **No DNS answer**: resolv.conf/search name, kube-dns Service/EndpointSlices, CoreDNS readiness/logs, TCP/UDP53 policy, VPC DNS flags, endpoint private DNS.
- **API timeout**: actual resolved destination → endpoint mode/public /32 or private route/SG/NACL → TCP443. Don't edit RBAC to fix a TCP timeout.
- **API 401/403**: current IAM role/token expiry/exec → access entry principal/auth mode → intended RBAC or EKS access-policy scope; no secret dump.
- **Pending Pod**: describe Pod events → CPU/memory/taints/affinity/PVC AZ → kubelet CNI errors/IP budget/ENI quotas. Scheduler success with FailedCreatePodSandBox points below scheduler.
- **Service times out**: direct ready PodIP test, EndpointSlice selector/port/readiness, source/destination policy, actual kube-proxy mode/rules/state; no fabricated VPC service route.
- **LB 502/503/unhealthy**: request listener/rule/TLS → LB healthy targets and target type → SG/NACL/health port/path → readiness/termination/webhook/controller IAM; ALB client header not transport source.
- **AWS AccessDenied**: caller identity role ARN, intended API and exact resource ARN → role trust/session identity versus permission/bucket/KMS/endpoint/SCP deny; changing Kubernetes ClusterRole doesn't grant AWS API permissions.
- **PVC stuck**: consumer existence / WaitForFirstConsumer, CSI controller identity/logs, storage provisioner mismatch, volume AZ/topology and attach limits. Never delete data to clear a UI status without backup decision.

Static local validation is in ../VALIDATION-LABS.md. IAM policy simulation, AWS dry-run support, kubectl server schema, Helm chart rendering, actual network behavior, availability and cost are NOT proven by bash syntax/YAML parsing.
