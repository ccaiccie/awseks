## B2 / V2 — separate deterministic native-policy acceptance from ordinary DNAT
“Our ordinary Service lesson still maps port eighty to port eight thousand eighty. For this provider-specific policy exercise, we deliberately use a separate Service with port eight thousand eighty at both ends. The clients are controlled by Deployments, not bare Pods. First prove that both clients reach the ready web Pod, that the independent sink is reachable, and that DNS works. Save the exact Pod identities and addresses. After policy converges, the permitted client must still reach the web application, and the unisolated client must still reach the sink. A blocked-client connection directly to the ready web Pod tests destination ingress. A permitted-client connection directly to the otherwise healthy sink tests source egress independently. A timeout by itself never proves that a policy caused the failure; correlate it with the agent and managed endpoint evidence.”

## B3 / F28 — eligibility, preparation, rollback, revalidation
“Eligible EKS clusters can return to the previous minor version within the documented seven-day window. Start with eligibility and rollback-readiness insights, and assess application, controller and API compatibility. Before the control plane goes back, prepare workers for the target version and downgrade any add-on that is incompatible with it. Wait until each changed add-on is active, ready and functioning, and recheck blockers. Standard managed-node and self-managed preparation is the operator’s responsibility. Auto Mode manages its node rollback before the control plane; Fargate needs the documented affected-Pod replacement plan instead. Only after these preparation gates should the control-plane rollback begin. Verify the applications, networking, storage and add-ons again afterward. This preserves existing data; it does not restore older application or database state.”

Do not say every addon must always be downgraded: only incompatible builds, selected from the target compatibility matrix. Do not suggest final validation substitutes for preparation, that addons roll back automatically, that arbitrary EKS downgrades are permitted, or that --force is the normal path. Preserve the separate Auto Mode Gateway API and version-sensitive Pod SG feature explanations and their existing caveats.
